# House style for screen mock-ups

This file is the base layer. The operator's prompt comes first, then the project's goals and use cases. Either one overrides any rule here. Each rule describes the feel of the product, never a layout to copy. Choose the arrangement, sizes and colours fresh for each product. Each rule ends with its reason.

1. **One window, one job.** The product opens straight into the work, with no splash or landing page. The user came to do one thing.
2. **Clean and minimal.** Show only what the current task needs. Every extra control competes with the work.
3. **Calm neutrals, one accent.** Pick one accent per product that suits what the product is about, and keep every other colour quiet. The accent then points at the selection and the main action.
4. **Dense but quiet.** Fit a useful amount on screen, and separate parts with spacing and light dividers. Decoration adds noise and no information.
5. **System fonts.** Use the platform's own typeface, and monospace only for code-like text such as paths, hashes and commands. The product feels native, and machine text stands apart.
6. **Every state designed.** Draw the empty, loading, error, and saved or done states, as well as the full one. Users meet these states first and most often.
7. **Errors in place.** Show an error where it happened, with the fact, the cause and the next step. The user can fix it without hunting.
8. **Nothing for show.** No pop-ups, tours, gradients, emoji, or animation that does not show progress. They slow the user and soon make the product look old.
9. **Keyboard first.** Every action works from the keyboard, and focus is always visible. Frequent users move faster, and nobody gets lost.
10. **Light and dark.** Both themes work, and the agent checks both. Users pick their theme, and a broken one looks like a broken product.
11. **Plain, short words.** Interface text uses short sentences, and says what happened and what is safe. Apply [Experience First](../../principle-experience-first/SKILL.md) to layout and copy. The user trusts the product and acts without guessing.
12. **Fake but realistic data.** Sample data looks real, and the agent invents every name, path and value. The mock shows real use and leaks nothing private.
