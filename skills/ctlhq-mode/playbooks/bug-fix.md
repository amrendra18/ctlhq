### Bug fix

**You own this task. Plan, review, verify.** Delegate investigation and the fix to subagents, stay in the lead. Pick each subagent's reasoning level and fast or standard speed for the job, per the Subagents section.

Be scientific. Every shipped line traces to runtime evidence. Belt-and-suspenders that "might help" is a hypothesis, not a fix. It does not ship. When evidence refutes a hypothesis, revert what it motivated. The smallest change the evidence justifies ships, nothing more.

1. Check ownership before any work. Re-read the report thread. Stop when a person clearly owns the fix, meaning they claim it, give a concrete implementation plan, or ask another agent to implement it. A bot that summarizes evidence, looks up logs, or posts a cause hypothesis does not own the fix. When an existing pull request or merged commit may fix it, verify that instead of a competing change. Reproduce the symptom twice on the baseline and confirm it is gone twice on the patched build, then report without authoring over it.
2. A triage reproduction receipt made on the current commit counts as the first of these runs. Reproduce it yourself on the matching surface via the surface's driver (Non-negotiables), even when a debug or instrumentation protocol says to ask the user to reproduce. Ask the user only with a stated, specific reason the control surface cannot reach the target, and only after driving it as far as it goes. If it won't reproduce directly, synthesize the trigger, tighten conditions, or instrument until it fires. Reproduce it twice on the real surface, with a read-only state cross-check. Name the correct and broken final states, observe the broken one, reset, and observe it again, and confirm a real state value without injecting or forcing the symptom.
3. Binary-search the cause. Form the candidate hypotheses, then rule them out until one survives. Seed them with `how` over the affected subsystem and the **why** skill for regression history. Each pass, take the split that cuts the most remaining problem space, get runtime evidence, eliminate. When program state is unclear, add instrumentation or logging and read it as the code runs. Don't guess. Drive a long or stubborn hunt with the host's `/loop` command (a Claude Code built-in) (in Codex, `/goal` per `playbooks/autonomous-run.md` step 2). Confirm the surviving *mechanism* with runtime evidence before the step-4 architect/interrogate fan-out.
4. Plan the fix. If it crosses a function boundary, `architect` first. Delegate implementation to a subagent using the model `ctlhq-models get bug-fix` prints with a specific scope.
5. Verify on the same surface. The original repro now passes. "Inconclusive" or wrong-surface is not a pass. Flag it. Unit tests show branch behavior, not bug absence.
6. Stage the commits so the failing repro lands before the fix in git history. See the **tdd** skill for the failing-test-first cadence when the bug has a cheap local test path. Skip it when the test would be expensive, integration-heavy, or unclear.
   This is the canonical **sequence-verifiable-units** principle skill, the failing test first and the fix on top.
7. Run **Opening a PR**. An unattended run opens a draft pull request only, and never merges or deploys.

**Reply:** what was broken, root cause, fix, how you verified. Paste failing-then-passing repro output verbatim.
